# ビリヤード（v309）

緑フェルト、木枠、金の金具、象牙色の数字玉を使う独立モード。

- `table.webp`: 提案画像を参照して画像生成した盤面（800×1200）。v303以降の画像は変更なし。玉・キュー・照準・演出はCanvas。
- 数字玉は **1・4・5が各2個、2・3が各3個、合計12個**。白い玉1個は別。未結合でシャッフルして開始。補充による数字の追加はしない。
- 数字どうしがぶつかると結合し、元の数字を保った塊として移動・回転する。
- **2〜4個で合計10になれば完成して得点。** 5・4・1、5・3・2、5・5も完成として扱う。通常テンクルの `calcPts` を使用。役なし1点、ワンペア2点、ツーペア3点、スリーカード4点、ストレート5点。
- スリーカードは2・2・2・4と1・3・3・3。ストレートは1・2・3・4。5・4・1、5・3・2、5・5は役なし。
- **バーストは廃止。** 合計10超、5個以上になる組み合わせ、4個で10未満になる組み合わせは結合せず反発。玉は消えず、配置待ちにもならず、得点・罰点も発生しない。AIも同じ結合条件を使う。
- **白い玉が塊に触れると全解除。** 元の位置で個別の玉へ戻し、接触の勢いと小さな分離運動を与える。同じ塊の玉どうしには0.8秒の再結合猶予。
- 10を完成させ続ける限り、連続回数に上限なく同じ人が打つ。完成しなかった場合に交代。結合できない接触が同じ一打で起きても、10が完成していれば手番は継続。打球回数の貯金はしない。
- 動きがすべて止まったら次に打つ人を決定。**完成に使った玉だけを、次の打者の相手が1個ずつ配置する。** 3個なら3個、2個なら2個を返す。複数完成した場合は全構成数字を返す。
- 配置は盤面のタップ、または押したまま動かして離す。重なり・盤外・担当以外・停止中の入力は拒否。全配置が終わるまで打球不可。配置中は次の打者を表示する。
- 15点先取。勝利判定は動きが止まったところで行い、勝利時は再配置せずリザルトへ。盤面＋配置待ちの在庫は常に1・4・5各2個、2・3各3個を維持。
- AIは3段階。同じ物理で試射し、得点・継続・相手へのチャンスを評価する。完成後の配置は次の相手が作りにくい位置を評価する。
- 打球は盤面のどこからでも引っぱって離す。**開始位置の24 CSS px以内へ指を戻して離せばキャンセル。** キャンセルボタンや専用領域は置かない。引っぱり中は既存の説明1行を操作案内に切り替える。
- キーボード：左右で角度、上下で強さ、Spaceで打球。引っぱり中のEscapeでキャンセル。配置は矢印で位置、Enter/Spaceで置く。OSによる操作中断やポインターキャプチャ喪失でも打たない。
- SEは打球・衝突・壁・結合・全解除・配置・役完成・追加打球・勝敗を合成。ミュート・停止・退出に対応。役完成は金の輪と得点演出。バースト用の演出・SE・配置処理は削除。

検証：`node tests/billiards.cjs`。数字12個の内訳、2〜4個での完成、5・4・1／5・3・2／5・5の実衝突、各役、連続成功と交代、結合不可時の反発・玉の保持・配置なし、完成後の配置担当、配置拒否・停止、全解除、勝利、AI、計105打の在庫保存と物理安定性を確認。v309のブラウザー検証でも上記3例の打球・完成・続行、AI完成後の3個配置、10超の衝突で玉が消えず交代することを確認。
