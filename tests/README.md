# PUZZLUX の確認

ゲームは従来どおり `index.html` を配信するだけで動きます。npm はテスト専用です。

```sh
npm ci
npm test
```

実際の `index.html` から画面部品・ミッション定義を読み、React 18 と jsdom で検証します。

- 0〜6ピース、全種類がそろったときの名前解放、完成絵、ボスクリア後の表示
- 次のミッション・報酬ピースの対応、既存セーブの保持
- ミッションとパネルの詳細表示、閉じる操作・Escape・フォーカス復帰
- リセットの確認とキャンセル
- 全6ミッションの成功・失敗条件、素材ファイルの参照

jsdom は見た目やタッチ操作を再現しません。テスト内の `showModal` は呼び出し確認用の代替です。実機では、縦長・背の低い画面での2:3比率、対戦ボタンの押しやすさ、詳細のスクロール、モーダル表示中に背後を操作できないことを確認してください。

## 表示の構造

`img/pzx/v250/` に新しい素材を置いています。完成絵、線画、6ピース、ヒビはすべて1024×1536です。各ピースは全キャンバスのまま同じ位置に重ねます。`thumb_*.webp` は報酬・結果画面向けの余白を除いた小画像です。

画面の高さを基準にヘッダー・パネル・進捗・対戦ボタンを配置しています。対戦ボタンの中心は通常の縦画面で高さ約58%が目安です。小さい画面では、文字とボタンの最小サイズを優先して下部をスクロールできます。

## 10秒ラッシュ（v253）

`rush-mode.cjs` は実際の App 内の対戦処理を読み込み、時計・音声・React の描画を代替して実行します。新モードの役得点、バースト、10秒を止めない場のリセット、期限ちょうどの得点拒否、引き分け、双方の5ラウンド先取、補充、退出時のタイマー取消、従来モードの得点処理を確認します。セーブの星やパズル進捗に変更がないことも確認します。ブラウザーでの操作速度・表示・効果音の聴感は、このテストでは検証しません。

ホーム → 10秒ラッシュ → 強さを選ぶ → チャレンジする。役の点数は従来どおり、バーストは相手に1点。得点後の場の切り替えは180msで時計は進み続けます。10秒終了時の得点が多い側に1ラウンド、同点は双方0。次のラウンドは1.8秒の結果表示とGOのあと開始し、双方に新しい手札を配ります。試合は5ラウンド先取で終了します。報酬ピースや本編の星は獲得しません。

## 十字キー操作（v281）

```sh
npm run test:controls
```

対戦手札は双方とも5列×2段の固定10枠です。十字キー（PCでは矢印キー）で選び、「出す」（Enter/Space）で1枚出します。カードを直接タップして出すことはできません。空き枠を飛ばさず、端では折り返しません。出した後もカーソル位置は変わりません。

ホームの「操作設定」、または対戦中の一時停止画面で十字キーを左右に切り替えられます。配置は `tenkuru.controlSide.v1` に保存し、ゲーム進捗の保存領域とは分離しています。現在の移動時間は両者とも1マス160ms（`HAND_NAV.stepMs`）。プレイ感は実機で調整する前提です。単独モード・テンフォール・チュートリアルの操作は従来どおりです。

テストは移動境界、最短経路、連打による待ち時間の迂回防止、空き枠・カード制約、一時停止・退出、CPU移動の取消、左右設定の保存を確認します。

既存試験の注意：基準コミット `d0e106c` の `survival-mode.cjs` は古い補充数（役なし0枚）を期待し、現在の補充数（役なし1枚）と一致しないため、変更前から最初の補充検証で失敗します。この変更では補充ルールを変更していません。`puzzlux-ui.cjs`、`rush-mode.cjs`、`charge-mode.cjs`、`cursor-controls.cjs` は個別に実行できます。
